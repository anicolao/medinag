# Local alert action functional diagnostic

Run `MEDINAG_E2E_STORY=local-alerts npm run ios:e2e:connected`.

This creates a schedule through the real administrator UI in isolated Firebase
emulators, follows it through the iPhone UI, permits actual local notifications,
observes the real system notifications and explicitly opens the app to respond,
and checks completion on the real administrator subscription. The clock mapping
accelerates deadlines, never delivery. The local journal's real saved/synchronized
events are observed through the Simulator log stream, not generated by the test.

Scenario inputs are saved through Settings: R = 10 minutes and S = 15 minutes.
At the explicit 0.002 time mapping these are 1.2 and 1.8 real seconds, keeping
both observable notification events within the two-second condition limit without
the multiple-per-second repeat storm of a three-minute compressed cadence.
Native unit tests separately verify the reviewed R = 3 / S = 10 examples.

This is explicitly a functional diagnostic, not an approved visual walkthrough.
No screenshot baselines are updated or pixel tolerances relaxed. The existing
US-004 walkthrough is historical and must be regenerated/reviewed against the
new UI before it can claim current visual coverage. Screenshots from this run
are diagnostic attachments. Physical sound, simultaneous phone/Watch routing,
unattended queue renewal, and automatic foreground app closure are not proven.
